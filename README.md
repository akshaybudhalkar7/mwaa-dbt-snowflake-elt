# mwaa-dbt-snowflake-elt

A data pipeline that copies data from an insurance company's system into a data warehouse
**every day**, cleans it, and turns it into tables that are ready for reports and dashboards.

## What problem does it solve?

An insurance company has a system that stores its **customers**, the **policies** they buy, and
the **claims** they make. That system is built for running the business, not for analysis. Asking
it questions like *"how much premium did we sell per city last month?"* or *"how many days does it
take to pay a claim?"* is slow and hard.

This project copies that data into **Snowflake** (a data warehouse) and reshapes it so those
questions become simple queries.

> The insurance data is made up (generated by code), so the project runs anywhere without real
> customer data.

## What happens every day

1. **Ask for what's new.** Airflow starts the daily run. A small program (AWS Lambda) asks the
   insurance system: *"give me everything that changed since last time."* It remembers where it
   stopped last time in a bookmark called the **watermark**.
2. **Save the raw data.** The answer is saved as files in **Amazon S3**, plus one small "receipt"
   file (the **manifest**) that lists exactly what was saved.
3. **Load it into Snowflake.** As soon as a file lands, **Snowpipe** copies it into Snowflake
   automatically, within about a minute.
4. **Check nothing was lost.** Airflow compares the receipt with what arrived in Snowflake. The row
   counts must match exactly before anything else happens.
5. **Clean and organise it (dbt).** The data moves through three layers:
   - **Bronze**: the raw data exactly as it arrived, duplicates included. Nothing is ever deleted.
   - **Silver**: cleaned and typed, with duplicates removed, and the full history of every change kept.
   - **Gold**: report-ready tables: customers, policies, dates, policies sold, and claims.
6. **Move the bookmark.** Only when every step and every data test has passed does the watermark
   move forward. If anything fails, it stays put and the next run simply tries the same data again,
   so nothing is skipped and nothing is counted twice.

```
Insurance system ──► Lambda ──► S3 files ──► Snowpipe ──► Snowflake: bronze ──► silver ──► gold
       ▲                                                                                    │
       └───────────── bookmark (watermark) moves only after all checks pass ◄───────────────┘
```

## What you can answer with the gold tables

- Premium sold per product, city and month
- Claims per status, and the average number of days from report to payment
- Where a customer lived **at the time** of a claim, even if they have moved since
  (the customer history is kept — "Slowly Changing Dimension Type 2")

## Built with

| Part | Tool |
|---|---|
| Runs the daily steps in order | Apache Airflow on **Amazon MWAA** |
| Pulls the data | **AWS Lambda** |
| Stores the raw files | **Amazon S3** |
| Loads files automatically | **Snowflake Snowpipe** |
| Data warehouse | **Snowflake** |
| Cleans and models the data, runs data tests | **dbt** |
| Creates all the AWS resources | **AWS CDK** (Python) |
| Deploys on every push | **GitHub Actions** |

No passwords or secret keys are stored anywhere: every component proves its identity through
AWS/Snowflake trust settings (Workload Identity Federation, OIDC).
